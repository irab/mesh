Routing Methods Compared

Meshtastic Managed Flooding

  • Listen before relay: A client schedules one relay, then cancels it if another node transmits the same packet first
  • Far nodes first: Weaker SNR gets a shorter contention window, so the node farther from the sender tends to relay before nearby nodes
  • Routers are the exception: A ROUTER relays in an earlier window and does not cancel when it hears another copy
  • Hop limit: The default is 3. A packet heard with hop limit 0 is not relayed. The maximum is 7
  • Known next hop: After a direct message learns its next hop, only that hop relays. Channel broadcasts keep using managed flooding

MeshCore Selective Routing

  • Path discovery phase: Initial flooding to find optimal route to destination
  • Route establishment: Creates a persistent path between nodes
  • Bandwidth efficiency: After path discovery, only nodes on the route forward packets
  • Selective forwarding: Nodes not on the established route drop packets
  • Adaptable routing: Routes can be re-established if network topology changes

Network Performance Considerations

Managed flooding still uses airtime for every relay that is not cancelled, so many simultaneous senders can congest a channel. It does not retransmit from every node that heard the packet. Selective routing avoids that fan-out once a path is known:

  • Network density: Dense networks benefit more from selective routing to reduce congestion
  • Node reliability: Unreliable or mobile nodes may benefit from flooding's redundancy
  • Message priority: MeshCore prioritizes direct routes (pri=0) and decays flood priority with hop count, while Meshtastic prioritizes ACKs, alerts, and reliable messages ahead of background telemetry in its TX queue
  • Power consumption: Selective routing typically requires less overall transmission, saving power across the network
